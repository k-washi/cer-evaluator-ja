# 正規化・評価の詳細

[使い方に戻る](../README.md)

**正解の各候補と認識結果の両方に、同じ正規化を適用します。英字は小文字にするため、`GPU` と `gpu`、`iPhone` と `iphone` の違いは誤りに数えません。**

正規化は `data/speech-ja-text-frontend` の `TextNormalizerCER` を基にし、`matcher/text_cer.py` のゼロ・番号・数値範囲・単位の規則も参考にしています。読み候補の生成や英単語のカタカナ化は行いません。必要な処理と辞書を同梱しているため、インストール後に `data/` は不要です。

### 処理の順序

1. 正解の注釈を解釈し、候補を全文に連結します。例えば `一(V 万|億)円` は `一万円` / `一億円` に展開します。
2. メールアドレスを退避して内部の記号・数字・空白を保護します。その上で、本文の前後の空白を除き、改行・タブ・連続空白を半角スペース1個に統一します。Unicode NFKCで文字幅や互換文字を統一し、日本語・記号・単位の前後の不要な空白を削除します。
3. 連続する長音記号 `ー` を1文字にまとめます。`ゼロ` を `0` に置き換え、数値に続く長さの単位と、電話番号・郵便番号のハイフンを統一します。
4. 数字に使われる文字を含む場合はSudachiで全文を形態素解析し、保護対象の語句や電話番号などの数字列を除いて数値表記を統一します。
5. `str.lower()` で英字を小文字にします。
6. 数値範囲の `から`・`〜`・`~` を `〜` に統一して末尾の `まで` を除きます。その後、**引用符・中黒・句読点・メール外の `!?` と小数点以外のピリオドだけを削除**し、メールアドレスを復元します。その他の記号は保持します。
7. 正規化後の文字列で編集距離とCERを計算し、CERが最小になる正解候補を選びます。

候補ごとに**全文を正規化**するため、数字・英単語・保護語句がタグの境界をまたいでも扱えます。`normalize(text)` は上記2〜6を行う関数で、注釈の解釈・候補選択は行いません。

### 文字幅・英字・空白・長音

以下の例は、すべての正規化処理を終えた結果です。

| 対象 | 入力例 | 正規化後 |
| --- | --- | --- |
| 英字の大小 | `GPU` / `gpu` / `ＧＰＵ` | `gpu` |
| 英語の商品名 | `iPhone` / `iphone` | `iphone` |
| 半角カタカナ | `ｶﾞｯﾂﾎﾟｰｽﾞ` | `ガッツポーズ` |
| NFKCの互換文字 | `①` / `㍿` | `1` / `株式会社` |
| 日本語同士・日本語と英数字の間の空白 | ` 私 は GPU を 使う。 ` | `私はgpuを使う` |
| 英単語間の連続空白 | `OpenAI   API` | `openai api`（空白1個を保持） |
| 英数字間の接続記号の前後の空白 | `COVID - 19` / `ASR / TTS` | `covid-19` / `asr/tts` |
| 数値と単位・通貨記号の間の空白 | `36 ℃` / `¥ 1000` | `36°c` / `¥1000` |
| 連続する長音 | `イェーーーーい！` | `イェーい` |

括弧の内側、句読点の直前などの空白も整理します。すべての空白を一律に消す処理ではなく、保持された英単語間の空白などはCERの1文字として数えます。NFKCは全角半角の統一に加え、丸数字や組文字も変換します。

### 数値と保護語句

漢数字と算用数字を揃え、整数は万未満を算用数字、万以上を `万`・`億` などの単位付きで表します。数値かどうかは文脈・品詞・同梱辞書に基づいて判定します。

| 対象 | 入力例 | 正規化後 |
| --- | --- | --- |
| カタカナのゼロ | `ゼロ` / `ｾﾞﾛ` / `ゼロ円` | `0` / `0` / `0円` |
| 数字列中のゼロ | `819ゼロ5` | `8万1905` |
| 漢数字 | `十三円` | `13円` |
| 万以上の整数 | `一万五千円` / `15,000円` | `1万5000円` |
| 桁区切り付き整数 | `10,737,418` | `1073万7418` |
| 日付 | `二千二十四年三月一日` | `2024年3月1日` |
| 四半期 | `第三四半期` | `第3四半期` |
| 範囲に含まれる数値 | `一〜三話` | `1〜3話` |
| 数値範囲の「から・まで」 | `3人から5人まで来ます` | `3人〜5人来ます` |
| 数値範囲のチルダ | `3～5まで` / `3~5` | `3〜5` |
| 数値に続くセンチ表記 | `3センチメートル` / `3センチ` / `3シーエム` / `3CM` | `3cm` |
| 数値に続くミリ表記 | `5ミリメートル` / `5ミリ` / `5エムエム` / `5MM` | `5mm` |
| 単位付きの範囲 | `3センチから5センチまで` | `3cm〜5cm` |
| 小数の桁区切り | `33,000.75ドル` | `33000.75ドル` |
| 小数の表記 | `10000.5` / `1.2億円` | そのまま保持 |
| 正しい3桁区切りではないカンマ | `10737,418` / `1,2,3` | `10737418` / `123`（数値変換後にカンマだけ削除） |
| 数字に見える文字を含む保護語句 | `第五人格` / `万歳` / `五月雨` | そのまま保持 |

小数部分は保持し、`10000.5` を `1万0.5` のようには変換しません。桁区切りはカンマを除いた数値と同じ結果になるよう、既存の万・億への変換を適用します（`1,234,567円` / `1234567円` → `123万4567円`）。

`ゼロ` は参照実装と同じ文字列置換で、単独の語だけでなく本文中でも `0` にします。`イチ`・`いち`・`れい` など、その他の読み仮名は数字に変換しません。固有名詞・一般語の保護は漢数字などの数値解析に対するもので、`ゼロ` の置換には適用しません。

範囲の正規化では左右の単位を保持します。`3人から5人まで` と `3人〜5人` は、どちらも `3人〜5人` になります。`春から秋まで` のような数値以外の表現、符号付きの範囲、`3-2` のようなハイフン表記は範囲に変換しません。`3-2` と `3対2` は引き続き別の表記です。`4/13` や `1/2` は読みへ変換せず、スラッシュを保持します。

漢数字を含む固有名詞や一般語の誤変換を避けるため、Sudachiの品詞と同梱の保護語句辞書を使います。再現性のためSudachi辞書は20260116版に固定しています。

### 電話番号・郵便番号

電話番号・郵便番号の形式に合うハイフンを削除し、区切りのない表記と同じ正規化結果にします。国内電話は0で始まる10桁または11桁、国際電話は `+` と8〜15桁、郵便番号は3桁-4桁を対象とします。これは表記の判定であり、実在する番号かどうかの検証ではありません。

| 入力例（いずれも同じ結果） | 正規化後 |
| --- | --- |
| `03-1234-5678` / `0312345678` | `0312345678` |
| `090-1234-5678` / `09012345678` | `09012345678` |
| `+81-90-1234-5678` / `+819012345678` | `+819012345678` |
| `012-3456` / `0123456` | `0123456` |
| `123-4567` / `1234567` | `123万4567` |

電話番号と、先頭0の7桁の郵便番号は数字列を保護し、先頭0の削除や万・億への変換を防ぎます。**先頭0のない郵便番号は、ハイフンを除いた一般の整数と同じ数値規則**で正規化します。例えば `123-4567` は `123万4567` になりますが、`1234567` と一致します。正規化結果はCER比較用で、番号の表示用ではありません。番号として認識されないハイフンは保持します。電話番号・郵便番号のハイフン除去は、一般の記号削除とは別の番号専用の規則です。

### 削除する句読点と、保持する記号

**削除対象を限定し、それ以外の記号は保持します。** 以下の削除対象は正解・認識結果の両方から除き、編集距離にも正解文字数にも含めません。メールアドレス内は削除処理の対象外です。

| 扱い | 対象 | 入力例 → 正規化後 |
| --- | --- | --- |
| 削除 | 引用符（`"`、`'`、`「」`、`『』`、`“”`、`‘’`、`«»`、`‹›`、`〝〞〟`） | `「こんにちは」` → `こんにちは` |
| 削除 | 中黒（`・`、`·`、`‧`） | `東京・大阪` → `東京大阪` |
| 削除 | 句点・読点・カンマ | `はい、こんにちは。` → `はいこんにちは` |
| 削除 | メール外の `!` / `?` | `こんにちは！？` → `こんにちは` |
| 削除 | 小数点以外のピリオド（メール外） | `Hello.` / `3.` → `hello` / `3` |
| 保持 | 小数点 | `３．１４！` → `3.14` |
| 保持 | 演算子・正負の符号 | `Ａ＋Ｂ＝Ｃ` → `a+b=c`、`3−2=1` → `3−2=1` |
| 保持 | ハイフン・アンダースコア | `a-b_c` → `a-b_c` |
| 保持 | 括弧・スラッシュなど数式にも使う記号 | `2*(3+4)=14` → `2*(3+4)=14` |
| 保持 | 範囲・単位・通貨・その他の記号 | `3〜5`、`50%`、`¥1000`、`★gpu★` |

NFKCによって全角の `＋＝！？` などは半角に統一してから扱います。Unicodeの「記号」カテゴリをまとめて削除する処理はありません。引用符として列挙した括弧は削除しますが、丸括弧・角括弧・波括弧や `【】` は保持します。コロン・セミコロンも保持します。

小数点は、NFKC適用後に**左右が半角数字である `.`** として判定します。`1.5` と `15` は別の文字列として評価します。これは前後の文字による判定なので、数字間のピリオドがバージョン番号などに使われている場合も保持します。メール以外では、数字に挟まれていないピリオドや連続したピリオドは削除します。URLやファイル名のピリオドを保護する特別な処理はありません。

### メールアドレスの保護

メールアドレスは正規化の最初に退避し、**内部の記号・数字列・空白を保持**します。文字幅の統一（NFKC）と英字の小文字化はメールにも適用します。

| 入力 | 正規化後 |
| --- | --- |
| `Foo.Bar+tag!?@example-domain.com!` | `foo.bar+tag!?@example-domain.com` |
| `「A_B-C+D=E@example.co.jp」へ。` | `a_b-c+d=e@example.co.jpへ` |
| `"a,b!?"@example.com!` | `"a,b!?"@example.com` |
| `100000+03-1234-5678@example.com` | そのまま保持（数値・電話番号の変換も適用しない） |

アドレス内の `!?` と、アドレスの後ろに付いた文末の `!?` を区別します。`a!@example.com` と `a@example.com`、`a.b@example.com` と `ab@example.com` は別の文字列です。引用符付きローカル部（`"a,b"@example.com`）の引用符・カンマも保持します。

保護対象は、ASCIIのローカル部（引用符付きにも対応）と、ドットを含むドメインまたはIPリテラルからなる形式です。メールの実在性を検証するものではなく、国際化メールアドレスなどすべての形式を判定するものでもありません。空白なしでアドレスの先頭に `!?` が続く場合は、有効なローカル部の文字として扱います。

`normalize()` の戻り値は**CER比較用の最終文字列**です。句読点削除によって数字が隣接する場合があるため、再度数値として正規化すると結果が変わることがあります。`cer()` / `evaluate()` には事前に正規化せず原文を渡してください。

### 同一視しない表記

大小文字の違いは吸収しますが、**読みや意味による言い換えは行いません**。例えば `iPhone` と `アイフォーン`、ひらがなとカタカナ、`まあ` と `まぁ` は自動では一致しません。許容する場合は `(V iPhone|アイフォーン)` などで候補を明示してください。また、注釈のない `えー` などを自動検出して削除する処理もありません。

```python
from cer_evaluator_ja import cer, normalize

assert normalize("GPU") == normalize("gpu") == "gpu"
assert normalize("iPhone") == normalize("iphone") == "iphone"
assert cer("GPU", "gpu") == 0.0
assert cer("iPhone", "iphone") == 0.0
assert cer("ゼロ", "0") == 0.0
assert cer("03-1234-5678", "0312345678") == 0.0
assert cer("3人から5人まで", "3人〜5人") == 0.0
assert cer("イチ", "1") > 0.0
assert cer("「東京」・大阪。", "東京大阪") == 0.0
assert cer("Hello.", "hello") == 0.0
assert cer("1.5", "15") > 0.0
assert cer("a+b=c", "abc") > 0.0
assert cer("a!?@example.com", "a@example.com") > 0.0
```

## CERの計算方法

CERは `編集距離 / 正規化した採用候補の文字数`。候補ごとに分母も変わるため、編集距離ではなく比率を最小化します。同率なら編集数、次に候補の記載順で決定します。正解が空の場合は分母を1とし、双方が空なら0、認識結果だけがある場合はその文字数を返します。CERは1を超える場合もあります。

## 速度と検証

タグ境界をまたぐ数値や語句を正しく扱うため、候補を全文に連結して正規化します。候補は逐次生成し、RapidFuzzによる編集距離計算、暫定最良値による探索打ち切り、4096件の正規化キャッシュ、数値を含まない文の形態素解析省略で処理を軽減しています。

候補数はタグ数に対して指数的に増えます。既定の上限は1発話10万候補で、超過時は近似値を返さず `CandidateLimitError` にします。Pythonの `max_candidates` / CLIの `--max-candidates` で変更でき、Pythonでは `None` で上限を解除できます。長い音声は対応する区間単位で評価してください。

```bash
uv run pytest
uv run ruff check src tests
uv run python tests/benchmark.py /path/to/annotations.jsonl
```

ベンチマークは認識結果を模した固定文字列で全候補の探索時間を測ります。ASR精度を測るものではありません。
